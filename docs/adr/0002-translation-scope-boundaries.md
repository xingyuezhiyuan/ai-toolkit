# 翻译范围边界：日志流与用户数据永不翻译，帮助文档移入二期

界面中文化存在四类文字，我们刻意只翻其中两类：**翻译对象** = 界面文案（菜单、按钮、表单标签与说明、占位符、前端报错与弹窗提示，含动态模板句）；**永不翻译** = Python 后端日志流（保留英文以便检索报错关键字、对照官方文档与 Discord 社区）和用户数据（数据集/任务名、路径、prompt 示例、YAML 内容——prompt 译入中文会误导训练输出）；**延后** = 内嵌帮助文档 docs.tsx（约 600-1000 个长句，且与配置字段语义耦合，待界面翻译流水线经 V2 巡检验证稳定后作为二期纯词典灌入工作纳入）。

## Consequences

- 有人在日志里"发现"英文不是 bug，是决议，不要试图"修好"它。
- 覆盖层的排除规则（textarea / pre / code / 日志区域跳过）是此边界的实现守护，而非权宜之计。
- 二期启动时不需要新机制，只是向同一份词典灌条目 + 用同一 V2 巡检验收。

## 修订（2026-10-21）：docs.tsx 已从"延后"移入翻译范围

二期提前启动，机制与当年预判一致：不新增运行时机制，仅向同一份词典灌条目。

- docs.tsx 的 31 条 ConfigDoc（标题 + 说明，共 86 个渲染文本节点）译入 `ui/src/i18n/data/docs.zh.ts`，由 `zh.ts` 以 `...docsExact` 合并，UI 标签同键时优先。
- 说明文字被 `<code>`/`<br/>`/链接拆成文本节点，覆盖层逐节点替换，因此译文按片段编写并按中文语序衔接；行内代码、路径、示例 prompt 保留英文（`docsAllowEnglish`）。这是覆盖层路线的已知质量上限，接受。
- 提取器（`tools/i18n/extract.mjs`）不再跳过 docs.tsx，并把 JSX 空白折叠为单空格，使词典键与渲染后的 DOM 文本一致；`coverage.test.ts` 继续作为零漏翻闸门。
